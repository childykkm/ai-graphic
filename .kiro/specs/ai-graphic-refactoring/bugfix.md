# Bugfix Requirements Document

## Introduction

AI Graphic 생성기는 현재 2143줄의 단일 컴포넌트로 구성된 React + Vite 기반 애플리케이션으로, 보안 취약점, 코드 구조 문제, 성능 이슈 등 10가지 주요 문제점을 가지고 있습니다. 이 버그픽스는 모든 문제를 체계적으로 해결하고, 모노레포(Monorepo) 아키텍처로 전환하여 프로덕션 레벨의 안정적이고 유지보수 가능한 애플리케이션으로 개선하는 것을 목표로 합니다.

현재 애플리케이션은 3가지 기능(Graphic, Concept, Floor)이 하나의 탭으로 통합되어 있으며, 이를 독립적인 앱으로 분리하고 Next.js 기반 라우팅 구조로 전환합니다.

## Bug Analysis

### Current Behavior (Defect)

#### 1. 보안 취약점

1.1 WHEN 사용자가 11개 이상의 이미지를 생성하려고 할 때 THEN 시스템은 하드코딩된 비밀번호 "Childy20251!"를 클라이언트 코드에 노출하고 클라이언트 사이드에서 검증함

1.2 WHEN API 키가 환경변수로 설정될 때 THEN 시스템은 `vite.config.ts`의 `define` 속성을 통해 API 키를 클라이언트 번들에 직접 주입하여 브라우저에서 접근 가능하게 함

1.3 WHEN 사용자가 브라우저 개발자 도구를 열 때 THEN 시스템은 `process.env.API_KEY` 또는 `process.env.GEMINI_API_KEY`를 통해 API 키를 노출함

#### 2. API 호출 및 Rate Limiting 문제

2.1 WHEN 여러 이미지를 생성할 때 THEN 시스템은 배치 크기를 2로 고정하고 배치 간 2초의 대기 시간만 설정함

2.2 WHEN API가 429 (Too Many Requests) 에러를 반환할 때 THEN 시스템은 재시도 로직 없이 즉시 실패함

2.3 WHEN 네트워크 오류나 타임아웃이 발생할 때 THEN 시스템은 부분적으로 성공한 이미지를 저장하지 않고 모든 결과를 폐기함

#### 3. 코드 구조 및 유지보수성 문제

3.1 WHEN 개발자가 코드를 수정하려고 할 때 THEN 시스템은 2143줄의 단일 `App.tsx` 파일에 모든 로직이 집중되어 있어 가독성과 유지보수성이 매우 낮음

3.2 WHEN 3가지 기능(Graphic, Concept, Floor)이 하나의 컴포넌트에 존재할 때 THEN 시스템은 탭 전환 시 모든 상태를 초기화하고 중복 코드가 다수 존재함

3.3 WHEN TypeScript를 사용할 때 THEN 시스템은 `any` 타입을 사용하고 API 응답 타입이 정의되지 않아 타입 안정성이 부족함

#### 4. 성능 및 메모리 문제

4.1 WHEN 대용량 이미지를 업로드하고 처리할 때 THEN 시스템은 모든 이미지를 Base64로 인코딩하여 메모리에 저장하므로 브라우저가 느려지거나 크래시될 수 있음

4.2 WHEN 생성된 이미지를 미리보기할 때 THEN 시스템은 원본 해상도 그대로 렌더링하여 불필요한 리소스를 소비함

4.3 WHEN 진행률을 표시할 때 THEN 시스템은 실제 API 응답과 무관하게 시뮬레이션된 가짜 진행률을 표시함

#### 5. 사용자 경험 문제

5.1 WHEN 이미지 생성이 진행 중일 때 THEN 시스템은 생성 취소 기능을 제공하지 않아 사용자가 중단할 수 없음

5.2 WHEN 에러가 발생할 때 THEN 시스템은 구체적인 에러 메시지를 제공하지 않고 일반적인 메시지만 표시함

5.3 WHEN 사용자가 API 키를 설정하지 않았을 때 THEN 시스템은 명확한 안내 없이 생성 버튼을 클릭할 때만 에러를 표시함

#### 6. 테스트 및 문서화 부재

6.1 WHEN 코드 변경이 발생할 때 THEN 시스템은 단위 테스트나 통합 테스트가 없어 회귀 버그를 감지할 수 없음

6.2 WHEN 새로운 개발자가 프로젝트에 참여할 때 THEN 시스템은 코드 주석, API 사용법, 배포 가이드가 부족하여 온보딩이 어려움

#### 7. 아키텍처 및 확장성 문제

7.1 WHEN 3가지 기능(Graphic, Concept, Floor)이 하나의 앱에 통합되어 있을 때 THEN 시스템은 각 기능을 독립적으로 배포하거나 확장할 수 없음

7.2 WHEN 공통 UI 컴포넌트나 유틸리티 함수가 필요할 때 THEN 시스템은 재사용 가능한 패키지 구조가 없어 코드 중복이 발생함

7.3 WHEN Next.js 기반 라우팅이 필요할 때 THEN 시스템은 Vite + React Router 구조로 되어 있어 SSR/SSG 기능을 활용할 수 없음

### Expected Behavior (Correct)

#### 1. 보안 개선

2.1 WHEN 사용자가 11개 이상의 이미지를 생성하려고 할 때 THEN 시스템은 서버 사이드에서 인증을 처리하고 클라이언트에 비밀번호를 노출하지 않아야 함

2.2 WHEN API 키가 필요할 때 THEN 시스템은 서버 사이드 환경변수로만 API 키를 관리하고 클라이언트에 절대 노출하지 않아야 함

2.3 WHEN 클라이언트가 API를 호출할 때 THEN 시스템은 서버 사이드 프록시를 통해 API 키를 안전하게 사용해야 함

#### 2. API 호출 안정성 개선

2.4 WHEN 여러 이미지를 생성할 때 THEN 시스템은 동적 배치 크기와 지수 백오프(exponential backoff) 전략을 사용하여 Rate Limit을 준수해야 함

2.5 WHEN API가 429 에러를 반환할 때 THEN 시스템은 자동으로 재시도하고 사용자에게 진행 상황을 알려야 함

2.6 WHEN 네트워크 오류가 발생할 때 THEN 시스템은 부분적으로 성공한 이미지를 저장하고 실패한 항목만 재시도할 수 있어야 함

#### 3. 코드 구조 개선

2.7 WHEN 개발자가 코드를 수정할 때 THEN 시스템은 기능별로 분리된 컴포넌트와 모듈로 구성되어 가독성과 유지보수성이 높아야 함

2.8 WHEN 3가지 기능이 존재할 때 THEN 시스템은 각 기능을 독립적인 앱(`apps/graphic`, `apps/concept`, `apps/floor`)으로 분리하고 공통 모듈을 `packages`에 배치해야 함

2.9 WHEN TypeScript를 사용할 때 THEN 시스템은 모든 타입을 명시적으로 정의하고 `any` 타입 사용을 최소화해야 함

#### 4. 성능 개선

2.10 WHEN 대용량 이미지를 처리할 때 THEN 시스템은 이미지 압축, 지연 로딩, 메모리 최적화를 적용하여 브라우저 성능을 유지해야 함

2.11 WHEN 생성된 이미지를 미리보기할 때 THEN 시스템은 썸네일을 생성하고 필요할 때만 원본을 로드해야 함

2.12 WHEN 진행률을 표시할 때 THEN 시스템은 실제 API 응답 상태를 기반으로 정확한 진행률을 표시해야 함

#### 5. 사용자 경험 개선

2.13 WHEN 이미지 생성이 진행 중일 때 THEN 시스템은 생성 취소 기능을 제공하여 사용자가 언제든지 중단할 수 있어야 함

2.14 WHEN 에러가 발생할 때 THEN 시스템은 구체적인 에러 메시지와 해결 방법을 제공해야 함

2.15 WHEN 사용자가 API 키를 설정하지 않았을 때 THEN 시스템은 명확한 안내와 설정 방법을 즉시 표시해야 함

#### 6. 테스트 및 문서화 추가

2.16 WHEN 코드 변경이 발생할 때 THEN 시스템은 단위 테스트와 통합 테스트를 통해 회귀 버그를 자동으로 감지해야 함

2.17 WHEN 새로운 개발자가 프로젝트에 참여할 때 THEN 시스템은 상세한 코드 주석, API 문서, 배포 가이드를 제공하여 온보딩을 지원해야 함

#### 7. 아키텍처 개선

2.18 WHEN 모노레포 구조로 전환할 때 THEN 시스템은 `apps` 디렉토리에 독립적인 앱(`graphic`, `concept`, `floor`)을 배치하고 `packages` 디렉토리에 공통 모듈(`assets`, `config`, `core`, `styles`, `ui`)을 분리해야 함

2.19 WHEN Next.js 기반 라우팅을 사용할 때 THEN 시스템은 `apps/[app-name]/src/routes/[route-name]/page.tsx` 구조를 따라야 함

2.20 WHEN 공통 UI 컴포넌트가 필요할 때 THEN 시스템은 `packages/ui`에서 재사용 가능한 컴포넌트를 제공해야 함

### Unchanged Behavior (Regression Prevention)

#### 1. 핵심 기능 유지

3.1 WHEN 사용자가 의류 이미지를 업로드할 때 THEN 시스템은 계속해서 Base64로 변환하고 Gemini API에 전달하는 기능을 유지해야 함

3.2 WHEN 사용자가 이미지 생성 옵션(비율, 크기, 수량 등)을 설정할 때 THEN 시스템은 계속해서 해당 옵션을 API 요청에 반영해야 함

3.3 WHEN 사용자가 생성된 이미지를 다운로드할 때 THEN 시스템은 계속해서 단일 다운로드 및 ZIP 다운로드 기능을 제공해야 함

#### 2. UI/UX 일관성 유지

3.4 WHEN 사용자가 드래그 앤 드롭으로 이미지를 업로드할 때 THEN 시스템은 계속해서 동일한 방식으로 작동해야 함

3.5 WHEN 사용자가 이미지 미리보기를 볼 때 THEN 시스템은 계속해서 업로드된 이미지를 즉시 표시해야 함

3.6 WHEN 사용자가 생성 버튼을 클릭할 때 THEN 시스템은 계속해서 로딩 상태를 표시하고 결과를 렌더링해야 함

#### 3. 프롬프트 생성 로직 유지

3.7 WHEN 시스템이 Gemini API 프롬프트를 생성할 때 THEN 시스템은 계속해서 `system_logic.md`에 정의된 프롬프트 구조를 따라야 함

3.8 WHEN 사용자가 시선/자세/시점 변화 슬라이더를 조정할 때 THEN 시스템은 계속해서 해당 값에 따라 프롬프트를 동적으로 생성해야 함

3.9 WHEN 사용자가 커스텀 프롬프트를 입력할 때 THEN 시스템은 계속해서 해당 내용을 최우선으로 반영해야 함

#### 4. 배치 처리 로직 유지

3.10 WHEN 여러 이미지를 생성할 때 THEN 시스템은 계속해서 배치 단위로 병렬 처리하고 배치 간 대기 시간을 적용해야 함 (단, 배치 크기와 대기 시간은 개선됨)

3.11 WHEN API 응답을 받을 때 THEN 시스템은 계속해서 `inlineData`에서 Base64 이미지를 추출하고 결과 배열에 추가해야 함

#### 5. 모달 및 에러 처리 UI 유지

3.12 WHEN 에러가 발생할 때 THEN 시스템은 계속해서 에러 모달을 표시해야 함 (단, 에러 메시지는 더 구체적으로 개선됨)

3.13 WHEN 사용자가 11개 이상 생성을 시도할 때 THEN 시스템은 계속해서 인증 절차를 요구해야 함 (단, 클라이언트 사이드 비밀번호 검증은 서버 사이드로 이동됨)

#### 6. 애니메이션 및 인터랙션 유지

3.14 WHEN 사용자가 UI와 상호작용할 때 THEN 시스템은 계속해서 Framer Motion 기반 애니메이션을 제공해야 함

3.15 WHEN 사용자가 섹션을 접거나 펼칠 때 THEN 시스템은 계속해서 부드러운 전환 효과를 제공해야 함
